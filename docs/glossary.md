# Glossary

## 1. Introduction

This glossary explains technical terms, application concepts and abbreviations used throughout the Waliin documentation.

## 2. Application and Technology Terms

| Term | Definition |
|---|---|
| Waliin | Healthcare equipment management system developed by Solvya. |
| Solvya | Company responsible for developing Waliin. |
| Frontend | User-facing part of the application. |
| Backend | Server-side application responsible for processing requests and application logic. |
| API | Application Programming Interface used for communication between software components. |
| REST API | API style that uses HTTP methods to access and manage resources. |
| Next.js | React framework used to build the Waliin frontend. |
| React | JavaScript library used to build user interfaces. |
| TypeScript | Programming language used in the frontend. |
| FastAPI | Python framework used to implement the Waliin backend API. |
| PostgreSQL | Relational database used to store application data. |
| SQLAlchemy | Python library used for database integration. |
| Alembic | Database migration tool used with SQLAlchemy. |
| Pydantic | Python library used for data validation and settings management. |
| Vitest | Test runner used by the frontend project. |
| pytest | Testing framework used by the backend project. |

## 3. Healthcare and Equipment Management Terms

| Term | Definition |
|---|---|
| Medical Equipment | Equipment used to support healthcare services and clinical activities. |
| Equipment Registration | Process of creating an equipment record in Waliin. |
| Equipment Record | Stored information describing a registered piece of equipment. |
| Equipment Document | File associated with an equipment record, such as a manual or warranty. |
| Equipment Status | Current operational or administrative state of equipment. |
| Installation Status | Recorded state of equipment installation and commissioning. |
| Equipment Fault | Reported problem affecting medical equipment. |
| Fault Reporting | Process of submitting an equipment fault through the application. |
| Fault Assessment | Technical evaluation of a reported equipment fault. |
| Biomedical Engineer | User role responsible for biomedical engineering activities. |
| Clinical Staff | User role associated with clinical equipment-related activities. |
| Health Manager | User role associated with health management activities. |
| Repair Record | Record documenting repair activities for a reported fault. |
| Repair Verification | Process of recording verification activities after a repair. |
| Maintenance Report | Report containing equipment maintenance information. |
| CSV Import | Process of importing equipment records from a comma-separated values file. |

## 4. Authentication and Security Terms

| Term | Definition |
|---|---|
| Authentication | Process of verifying a user's identity. |
| Authorization | Process of determining what an authenticated user can access. |
| Session | A period during which a user remains authenticated. |
| Session Cookie | Browser cookie used to maintain an authenticated session. |
| Multi-Factor Authentication (MFA) | Authentication process involving an additional verification factor. |
| Password Hashing | Process of transforming a password into a protected representation. |
| Argon2 | Password-hashing algorithm used by the backend. |
| Role-Based Access | Approach to organizing access according to user roles. |

## 5. Database and API Terms

| Term | Definition |
|---|---|
| Database | Organized collection of application data. |
| Relational Database | Database that stores information in related tables. |
| Database Table | Structure that stores records in rows and columns. |
| Primary Key | Column or combination of columns that uniquely identifies a database record. |
| Foreign Key | Column that references a record in another table. |
| Database Migration | Versioned change to the database schema. |
| Index | Database structure that helps improve data retrieval performance. |
| Database View | Virtual table based on a database query. |
| HTTP | Protocol used for communication between the frontend and backend. |
| GET | HTTP method used to retrieve resources. |
| POST | HTTP method commonly used to submit data or create resources. |
| PATCH | HTTP method used to partially update a resource. |
| PUT | HTTP method used to replace or update a resource. |
| DELETE | HTTP method used to remove a resource. |
| JSON | Data format used for structured API communication. |
| HTTP Status Code | Numeric response indicating the outcome of an HTTP request. |
| Endpoint | Specific API URL through which an operation can be accessed. |
| Request | Message sent by a client to an API. |
| Response | Message returned by an API after processing a request. |
